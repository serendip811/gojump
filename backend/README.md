# GoJump backend

Python 표준 라이브러리만 사용하는 첫 데이터 수집 서버입니다.

## fixture 모드

API 키 없이 앱과 서버 연결을 확인합니다.

```sh
python3 -m backend.server --port 8080
curl http://127.0.0.1:8080/health
curl http://127.0.0.1:8080/v1/markets/seoul/snapshot
```

## 국토부 실거래가 모드

공공데이터포털에서 `국토교통부_아파트 매매 실거래가 자료` 활용신청 후 프로젝트 루트의 `.env`에 키를 저장합니다. `.env`는 Git에서 제외되어 있습니다.

```sh
DATA_GO_KR_SERVICE_KEY=발급받은-일반-인증키
ECOS_API_KEY=발급받은-ECOS-인증키
HOUSTAT_API_KEY=발급받은-HOUSTAT-인증키
```

서버는 시작할 때 `.env`를 자동으로 읽습니다. 셸 환경변수에 같은 이름이 이미 있으면 셸 값을 우선합니다. `ECOS_API_KEY`와 `HOUSTAT_API_KEY`가 없으면 각 기관의 개발용 샘플 응답을 사용하지만, 운영 배포 전에는 전용 인증키를 발급받아야 합니다.

```sh
python3 -m backend.server --port 8080 --month 202607
```

서버 시작 시 다음 데이터를 수집해 스냅샷을 메모리에 보관합니다.

- 서울 25개 자치구의 지정 월·전월 거래량: 취소 거래 제외
- 한국은행 기준금리: `722Y001 / 0101000`
- 예금은행 신규취급액 기준 주택담보대출 금리: `121Y006 / BECBLA0302`
- 서울 미분양주택: `901Y074 / I410B`
- 서울 주택구입부담지수(K-HAI): HOUSTAT `T186503126543136 / 서울`
- 서울 아파트 입주예정물량: 서울주택 정보마당 당해연도 포함 2년 전망
- 서울 아파트 입주·분양 장기 시계열: KB부동산 데이터허브·프롭티어
- 저유동성 주택 거래: 국토교통부 실거래가 24개월 자체 분석

저유동성 분석은 최초 한 번 서울 24개월 실거래를 SQLite에 적재해야 합니다. 기본 설정은 공공데이터포털의 요청 제한을 피하기 위해 단일 작업과 0.5초 간격을 사용하며, 완료된 구·월은 재실행 시 건너뜁니다.

같은 실거래 SQLite에서 서울 월별 거래 건수를 집계해 거래량 상세 그래프로 전달합니다. 앱은 실제 건수를 `2년·5년` 범위로 표시하며 거래량 위험점수 그래프와 구분합니다. 거래량 Y축은 선택 범위가 바뀌어도 0부터 공통 상한을 사용합니다.

HOUSTAT에서 받은 서울 K-HAI 전체 분기 시계열도 같은 SQLite 파일의 `khai_observations` 테이블에 증분 저장합니다. API 스냅샷은 상세 그래프용 전체 원지수와 기간 라벨을 함께 내려주며, 앱에서 최근 2년·5년·전체 범위를 선택합니다.

ECOS의 주택담보대출 월별 금리 10년 이력과 한국은행 일별 기준금리는 각각
`mortgage_rate_observations`, `base_rate_observations`에 저장합니다. 기준금리는
각 주담대 관측월 말의 최신값으로 정렬해 같은 `0~8%` 축에 점선으로 표시하며,
앱에서 `2년·5년·10년` 범위를 선택합니다.

ECOS 서울 미분양 월별 시계열은 `unsold_observations`에 증분 저장합니다. 미분양은 청약 점수에 중복 가산하지 않으며 기본 UI에도 노출하지 않습니다. 향후 하락 확인 분석을 위해 API 보조 필드와 SQLite 원자료는 유지합니다.

한국부동산원 지역별 청약 경쟁률 CSV의 서울 일반·특별공급 원자료는
`subscription_observations`에 저장합니다. 공식 제공 범위는 2020년 2월부터이며,
공급이 없었던 달은 경쟁률 0이 아니라 관측 없음으로 취급합니다. 분석용 경쟁률은
최근 3개월 접수건수 합계를 공급세대수 합계로 나눈 공급량 가중값을 사용합니다.
`python3 -m backend.backtest_subscription`으로 원자료 갱신과 가격 하락 백테스트를
재실행할 수 있습니다.

`python3 -m backend.backtest_rate`는 저장된 ECOS 주택담보대출·기준금리를 각 월
당시까지의 이력으로 다시 점수화하고, 서울 아파트 3개월 평균 거래금액의 향후
6·12개월 하락 여부와 비교합니다.

```sh
python3 -m backend.backfill --end 202607 --months 60
```

금리 점수의 첫 산식은 주담대 금리의 최근 10년 백분위 70%, 최근 3개월 변화 20%, 기준금리 절대 수준 10%다.

청약 위험점수는 3개월 가중 경쟁률의 절대 수준 50%, 전년 대비 냉각 50%로 계산합니다. 직전 3개월 변화는 점수에 가산하지 않습니다. 최근 3개월 공급이 300세대보다 적으면 점수를 중립 50 방향으로 축소합니다. 미분양의 기존 점수 산식은 백테스트 비교용으로 남기되 종합점수에는 사용하지 않습니다.

주택구입부담 점수는 K-HAI의 공식 기준점 100 대비 절대 수준 80%, 최근 1년 변화 20%다. K-HAI 자체에 주택담보대출 금리가 포함되므로 점수 내부에서 금리를 다시 가산하지 않는다. 상세 그래프는 이 0~100 위험점수가 아니라 K-HAI 원지수를 표시하며, 공식 부담 기준선 100을 함께 보여준다. HOUSTAT 장애 시 전체 스냅샷을 실패시키지 않고 기존 실데이터를 제공한다.

공급 점수는 KB 서울 입주물량의 직전 10년 연평균과 현재 연도를 포함한 향후 2년 예정 연평균을 비교한다. 평균과 같으면 50점이며 많을수록 공급 증가에 의한 고점 위험을 높게 본다. KB 입주·분양 연도별 원자료는 각각 `kb_move_in_observations`, `kb_pre_sale_observations`에 저장한다. 서울주택 정보마당의 공식 2년 전망은 집계 범위 차이를 확인하는 교차검증 및 KB 장애 시 폴백으로 유지한다.

저유동성 분석 단위는 `자치구·법정동·지번·단지명·10㎡ 면적구간`이다. 과거 21개월 거래 빈도 하위 20%를 저유동성군으로 고정하고, 최근 3개월의 거래 비중 50%, 이전 최고가 이상 비중 30%, 거래군 확산도 20%를 결합한다. 개별 단지를 공개하지 않고 서울 전체 익명 통계만 제공한다.

## 정적 JSON API 생성

로컬 서버 없이 GitHub Pages에 게시할 동일 스냅샷을 파일로 만들 수 있습니다.

```sh
python3 -m backend.export_static_api
```

기본 출력은 `public/api/v1/markets/seoul/snapshot.json`입니다. Actions에서는 `--require-live`로 API 키, 최소 5개 실데이터 지표, JSON 스키마를 검증한 뒤에만 Pages에 배포합니다.

## 현재 제한

- 실거래 신고 지연 때문에 최근 월 거래량은 잠정치다.
- 거래량 점수는 최근 3개월 평균을 기준으로 전년 같은 3개월 50%, 직전 3개월 20%, 과거 5년 같은 계절 30%를 결합한다. 6개월 미만 데이터만 있을 때 전월 대비 산식으로 폴백한다.
- 여섯 지표 모두 공식 또는 실거래 기반 데이터로 전환했다. 지역별 PIR은 모집단 한계 때문에 서울 K-HAI로 교체했고, 청약은 한국부동산원 일반공급 경쟁률을 사용한다. 서울 미분양은 청약 상세의 후행 확인 신호로 분리했다.
- 입주예정물량은 문서화된 Open API가 아니라 서울시 공개 화면용 JSON이므로 응답 구조 변경 가능성이 있다. 실패 시 이전 4개 실데이터 스냅샷을 유지한다.
- 최근 월 실거래는 신고기한과 취소 반영 때문에 잠정치이며 서버 시작 시 최신 월만 다시 수집한다.
- 서버를 재시작할 때만 원자료를 다시 수집한다. 배포 단계에서는 예약 수집과 영구 저장소를 추가해야 한다.
